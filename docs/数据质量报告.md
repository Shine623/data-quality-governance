## 四、典型问题案例

### 案例 1：同一客户多条记录

```
C0001  张伟   13800138000  北京市 朝阳区 建国路88号
C0004  张伟   13800138000  北京市朝阳区建国路88号
C0009  张 伟  13800138000  北京市 朝阳区 建国路88号
```

**问题**：同一客户在三个系统里各有一条记录，地址格式还不同。

**处理**：按手机号精确匹配判定为同一客户，保留 C0001，删除 C0004、C0009。

### 案例 2：疑似同名不同人

```
C0013  张三丰  18900189000  北京市 朝阳区 建国路99号
C0014  张三峰  18900189000  北京市 朝阳区 建国路99号
```

**问题**：姓名编辑距离 1，手机号相同，地址相同。

**处理**：手机号相同 → 判定为同一人，但姓名需人工核实哪个正确。

### 案例 3：疑似不同人

```
C0015  李四  18800188000  北京市 海淀区 学院路1号
C0016  李斯  18700187000  北京市 海淀区 学院路2号
```

**问题**：姓名编辑距离 1，但手机号不同、地址不同。

**处理**：标记为「疑似」但不合并，交人工确认。

## 七、建议

1. **源头治理**：三个老系统的录入界面加校验，从源头减少脏数据
2. **建立主数据管理**：确定唯一数据源，其他系统从主数据同步
3. **定期质量检查**：每周跑一次规则校验，问题进工单
4. **明确责任人**：每条规则都要有 owner，不能「大家都有责=没人负责」
