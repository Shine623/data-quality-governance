# 客户主数据质量治理与报表自动化

12 万条客户主数据的质量诊断、清洗规则设计、批量修复与报表自动化。

## 背景

客户提供了一份 12 万条的客户主数据（从三个老系统合并而来），问题很多：

- 同一客户在不同系统里有不同编码
- 手机号格式五花八门（带空格、带横线、位数不对）
- 必填字段大面积缺失
- 地址写得很随意（「北京朝阳」和「北京市朝阳区」混用）

业务方每月还要手工汇总 8 张 Excel 报表，一个人做要 6 小时。

本项目的目标：**先把数据质量摸清楚，再把清洗和报表都脚本化。**

## 技术栈

| 环节 | 工具 |
|---|---|
| 数据画像 | pandas / numpy |
| 模糊匹配 | difflib（编辑距离）+ 自定义规则 |
| 地址标准化 | 行政区划词典 + 正则 |
| 结果输出 | openpyxl（带样式的 Excel） |
| 调度 | Windows 任务计划 / cron |

## 治理流程

```
数据画像 → 规则设计 → 规则实现 → 批量清洗 → 效果评估 → 报表自动化
   ↓          ↓          ↓          ↓          ↓          ↓
 摸清问题   定 5 类规则  写脚本    分批修复   前后对比   固化模板
```

## 关键设计

### 1. 数据画像（先摸清问题）

不画像就清洗，等于闭着眼睛改数据。画像要回答三个问题：

1. **有多少条**：总行数、去重后行数
2. **哪里有问题**：每个字段的缺失率、格式错误率、重复率
3. **问题有多严重**：影响哪些下游业务

画像脚本输出示例：

```
字段名          总数      缺失      缺失率    格式错误   错误率
customer_name   120,000   1,240     1.03%     0         0%
phone           120,000   8,600     7.17%     1,100     0.92%
address         120,000   12,300    10.25%    0         0%
tax_no          120,000   45,000    37.50%    320       0.27%
```

### 2. 五类数据质量规则

| 类型 | 定义 | 本项目中的例子 |
|---|---|---|
| 完整性 | 必填字段不能为空 | customer_name、phone 不能空 |
| 唯一性 | 同一实体不能重复 | 「手机号 + 姓名」不能重复 |
| 有效性 | 值符合格式规范 | 手机号必须 11 位、1 开头 |
| 一致性 | 跨字段/跨表逻辑一致 | 地址里的省市区必须能对上行政区划 |
| 及时性 | 数据在合理时间范围内 | 更新时间不能早于创建时间 |

每条规则都要明确：**校验逻辑、责任人、处理动作**。

### 3. 模糊去重

同一客户可能有细微差异，比如：

| 记录 A | 记录 B | 是否同一人 |
|---|---|---|
| 张伟 | 张伟 | 是（手机号相同） |
| 张伟 | 张 伟 | 是（去空格后相同） |
| 张三丰 | 张三峰 | 可能（编辑距离 1） |
| 李四 | 李斯 | 否（编辑距离 1 但读音不同） |

**判定策略（三级）**：

1. **精确匹配**：手机号完全相同 → 直接判定重复
2. **强规则**：手机号相同 + 姓名去空格后相同 → 判定重复
3. **弱规则**：姓名编辑距离 ≤ 1 且地址相似度 > 0.8 → 标记为「疑似」，人工确认

不用纯编辑距离的原因：中文里「张三丰/张三峰」编辑距离只有 1，但可能是两个人；「李四/李斯」也是。必须结合地址、手机号等辅助字段。

### 4. 地址标准化

| 原始 | 标准化后 |
|---|---|
| 北京朝阳 | 北京市 朝阳区 |
| 北京市朝阳区 | 北京市 朝阳区 |
| 北京朝阳区建国路 | 北京市 朝阳区 建国路 |
| 京朝阳 | 北京市 朝阳区 |

**做法**：

1. 建立行政区划词典（省/市/区三级，约 3000 条）
2. 用别名映射（「京」→「北京市」、「沪」→「上海市」）
3. 正则提取 + 词典匹配
4. 匹配不上的保留原文，标记待人工处理

### 5. 报表自动化

原来 8 张手工报表：

| 报表 | 数据来源 | 原耗时 |
|---|---|---|
| 客户总量统计 | 客户表 | 30 min |
| 新增客户月报 | 客户表 + 创建时间 | 45 min |
| 客户分布（按地区） | 客户表 + 地址 | 60 min |
| 客户分布（按行业） | 客户表 | 40 min |
| 重复客户清单 | 客户表 | 90 min |
| 数据质量月报 | 客户表 | 50 min |
| 大客户 TOP50 | 客户表 + 交易表 | 30 min |
| 客户变更记录 | 客户表 + 日志表 | 35 min |

**脚本化后：一次运行 15 分钟，全部生成。**

## 快速开始

```bash
pip install pandas openpyxl

# 1. 数据画像
python src/profile.py --input samples/sample_customers.csv

# 2. 规则校验
python src/rules.py --input samples/sample_customers.csv --report quality_report.xlsx

# 3. 清洗
python src/clean_phone.py --input samples/sample_customers.csv --output cleaned.csv
python src/clean_address.py --input cleaned.csv --output cleaned2.csv

# 4. 去重
python src/dedupe.py --input cleaned2.csv --output deduped.csv

# 5. 生成报表
python src/report.py --input deduped.csv --outdir reports/
```

## 成果

| 指标 | 治理前 | 治理后 |
|---|---|---|
| 数据准确率 | 82% | **96%** |
| 重复记录 | 3,400+ 条 | 312 条（保留待人工确认） |
| 手机号格式错误 | 1,100+ 条 | 0 |
| 必填字段缺失 | 800+ 条 | 12 条（原件确实没有） |
| 报表生成耗时 | 6 小时 | 15 分钟 |

## 踩过的坑

1. **一开始就想全自动清洗，结果改错了很多数据**
   最初写了个脚本把「所有 11 位以下手机号补 0」，结果把一些本来就不是手机号的字段（比如座机）也改了。
   解决：清洗前先做字段语义判断（11 位且 1 开头才是手机号），不确定的标记为「待确认」而不是直接改。

2. **模糊去重阈值调了很久**
   编辑距离阈值设 1，把「张三丰/张三峰」判成同一人（错）；设 0，又漏掉了「张 伟/张伟」（漏）。
   解决：改成多条件组合——手机号精确匹配优先，其次姓名 + 地址相似度，最后才是编辑距离。且编辑距离 ≤ 1 的只标记不合并。

3. **地址标准化词典不全**
   第一版词典只有 300 个市区，覆盖率只有 60%。
   解决：从国家统计局网站抓了完整的行政区划数据（约 3000 条），覆盖率提到 94%。剩下 6% 保留原文。

4. **pandas 处理 12 万行时内存爆了**
   一开始用 `df.apply` 逐行处理地址，12 万行跑了一小时还没完，内存吃到 8G。
   解决：改用向量化操作（`str.extract` + `map`），耗时降到 2 分钟，内存 400MB。

5. **Excel 报表样式丢失**
   用 `df.to_excel` 导出，格式全没了，还得手工调。
   解决：改用 openpyxl 逐单元格写，并封装了一个 `apply_style` 函数复用样式。

6. **报表里的「异常数据标红」不好做**
   最初想用条件格式，但 Excel 的条件格式规则在不同版本表现不一致。
   解决：直接在写单元格时判断并设置填充色，不依赖条件格式。
